# Парсер реестра

## Запуск на своём CSV

Из корня проекта (нужен Go 1.24 или новее):

```powershell
cd backend
go run ./cmd/parse-registry ../owners_registry.csv
```

Команда выводит полный JSON-массив объектов, возвращённых парсером.
Для сохранения в UTF-8 файл:

```powershell
go run ./cmd/parse-registry -out ../owners_registry.json ../owners_registry.csv
```

Выходной файл должен быть новым; существующие файлы команда не перезаписывает.
При ошибке CSV команда сообщает причину в stderr и завершается с кодом 1.
Флаги нужно указывать перед путём к CSV. БД и запуск бота не нужны.

## Формат данных

`ParseCSV(io.Reader) ([]Ownership, error)` возвращает список записей
«один правообладатель — одно помещение». Это данные загруженного реестра:
парсер не создаёт сущности дома или собственника в БД и не объединяет людей по ФИО.
При ошибке возвращается `nil`, а не частичный результат.

CSV: UTF-8 (можно с BOM), разделитель `;`, запятая или табуляция.
`DetectDelimiter(header []byte) (rune, error)` отдельно определяет разделитель
по заголовку реестра с учётом кавычек и обязательных столбцов. Она возвращает
символ разделителя, не изменяя данные. `ParseCSV` вызывает её и устанавливает
`csv.Reader.Comma`. Буферизуется только заголовок (до 64 КиБ), далее записи
читаются из потока, UTF-8 проверяется по ячейкам. В памяти по-прежнему хранится
возвращаемый список объектов, но отдельной копии всего исходного файла нет.
Обязательные столбцы: `№ помещения`, `Адрес объекта`,
`Правообладатель (правообладатели)`, `Долевая площадь, м²`, `Общая площадь, м²`.
Площади возвращаются положительными десятичными строками с точкой без округления.
`OwnedArea` — площадь в собственности конкретного владельца, `FlatArea` — площадь
всего помещения. Общую площадь нельзя суммировать по владельцам: она повторяется.

Необязательные столбцы:

| Столбец CSV | Поле структуры |
| --- | --- |
| Доля собственника | Share |
| Кадастровый номер объекта | CadastralNumber |
| Вид помещения | PremisesType |
| Вид собственности | OwnershipType |
| Запись в ЕГРН, № | RegistrationNumber |
| Дата регистрации права | RegistrationDate |
| Дата присвоения кадастрового номера | CadastralAssignmentDate |
| Номер выписки | ExtractNumber |
| Дата выписки | ExtractDate |

`Share` сохраняется буквально, например `1/2`, `9/20` или текстовое описание.
Отсутствующая доля остаётся пустой: она не вычисляется из округлённой площади.
Даты остаются текстом, без проверки календарного формата.
`ObjectAddress` сохраняет адрес помещения, `HouseAddress` — адрес без конечного
суффикса квартиры/помещения. `SourceLine` — номер физической строки CSV.
`SourceFields` содержит все исходные значения ячеек с нормализованными заголовками,
включая неизвестные столбцы; это позволяет позже расширить модель без потери данных.

## Несколько владельцев

У CSV нет объединённых ячеек. Рекомендуемый экспорт — отдельная строка на каждого
владельца с повторением данных помещения:

```csv
№ помещения;Адрес объекта;Правообладатель (правообладатели);Доля собственника;Долевая площадь, м²;Общая площадь, м²
5;Дом 1, кв. 5;Иванов Иван;1/2;30;60
5;Дом 1, кв. 5;Петров Пётр;1/2;30;60
```

Поддерживаются и строки-продолжения: пустой `№ помещения` означает владельца
предыдущего помещения. Наследуются номер, адрес, кадастровый номер, вид помещения,
общая площадь и дата присвоения кадастрового номера. Непустые значения этих полей
должны совпадать с предыдущей строкой. Для нового помещения обязательно указывать
его номер; другие обязательные данные новой строки должны быть заполнены.
ФИО, доля, долевая площадь, вид собственности, запись права и сведения о выписке
не наследуются. Исходные пустые ячейки остаются пустыми в `SourceFields`.

Имена нескольких владельцев в одной многострочной ячейке не разбиваются автоматически:
парсер отклоняет такую запись. Переносы внутри одного имени тоже требуют подготовки
CSV. Несколько имён, записанных в одну строку, невозможно надёжно распознать — при
экспорте необходимо обеспечить правило «одна строка — один владелец».
Суммы долей и площадей по помещению не проверяются: реестр может быть неполным,
а исходные площади — округлёнными. Парсер проверяет лишь, что площадь владельца
положительна и не превышает площадь помещения.

Для хранения реестра как единого документа список можно связать с идентификатором
загрузки на уровне приложения; отдельные справочники домов/людей для этого не нужны.
Перед вызовом парсера приложение должно ограничивать размер загружаемого файла.
